# 学习通材料读取与成绩评语回传：能力证据与缺口

调查日期：2026-11-25（Asia/Shanghai）。对应研究票：[学习通材料读取与成绩评语回传有哪些已证实能力和缺口？](https://github.com/wozhendeshifwa/xuexitong_zuoye/issues/3)。

## 结论与边界

旧项目提供了教师会话下读取名单、单个批阅页、PDF 附件和成绩模板，以及按答卷标识写总分的实现证据。它不足以证明新项目所需的页面内作答、独立照片、多附件、平台参考答案自动提取、逐题分数与评语回传已经具备。这里的“未证实”不等于“学习通不支持”。

本次只读取旧项目文档与源码；没有登录或调用学习通、没有读取学生材料或凭证、没有写成绩。未获得平台官方稳定 API 契约，不能把旧项目观察视为平台承诺。下述结论只解决“现有证据是什么”，不决定产品范围、评分规则或用户工作流。

## 证据等级

- **静态实现**：本次在旧项目源码中直接确认的调用与判断逻辑；不代表当前平台调用成功。
- **历史记录**：旧项目维护者的接口经验文档；本次没有复现实验。
- **未证实**：未在本次检查范围找到足够实现或官方契约，留待后续验证。
- **推导风险**：由静态逻辑直接推导的适用边界，不声称已在生产发生。

## 关键事实对后续讨论的影响

1. **附件与提交必须分开讨论。** 旧实现的“有附件才算有效提交”与已确认的页面直接作答范围不一致。需要决定有效提交的业务含义，并验证页面可读字段；此报告不更改首版范围。[S3]
2. **参考答案上平台与评分器会用它是两件事。** 要验证题目、分值、答案及附件之间的对应，不能把本地答案 JSON 视为平台实时来源。[S1][S6]
3. **回传确认应区分 HTTP 成功、业务成功和回读一致。** 旧模块只在总分维度形成部分链路；未证实逐题和评语维度。[S5][S7]
4. **不得承诺平台回滚、原子批量或免副作用重试。** 当前只有本地恢复逻辑和历史写入经验，没有平台保证。[S1][S2][S5]
5. **人工改分冲突不能仅凭差异自动覆盖。** 现有对账能发现本地与平台差异，但没有已证实的平台并发条件写入能力。[S1][S7]

## 候选最小验证问题（后续授权后开展，本次未执行）

使用教师提供的隔离测试课程与合成学生提交，不触碰正式班级：

- 名单超过一页、空提交、纯页面文字、独立图片、PDF、多附件：分别验证完整读取和作答区边界，核对页面总数与所得对象数。
- 同一作业包含文本答案、公式、图片参考答案和缺失分值：检查题目、答案、分值的对应，以及修改后的变化检测。
- 隔离答卷验证总分、逐题得分、总评语和逐题评语分别能否写入并从页面及导出读回；没有相应能力时再讨论替代方式。
- 使用合成数据验证半分、回读延迟、重复请求、响应丢失、中断、部分失败、平台人工改分及确认后重交。
- 验证哪些操作改变“未交/已交/已批”等状态；不先假定可以恢复。
- 验证会话过期、无权限、返回登录页、页面结构变化时是否能明确停止，而不是被解释为“没有学生/没有答案”。

这些是供后续决策票使用的验证候选，不是已批准的真实平台测试或设计结论。
